# Claude Code Efficient Prompt Templates

## 🎯 Quick Reference: When to Use Which Model

```
HAIKU ($1/$5 per 1M):
- File operations
- Running tests
- Fixing syntax/lint errors
- Simple refactoring
- Code formatting
- Straightforward implementations from clear specs

SONNET ($3/$15 per 1M):
- Moderate complexity debugging
- Multi-file refactoring
- Test writing
- Documentation generation

OPUS ($15/$75 per 1M):
- Architecture design
- Complex debugging
- Performance optimization
- Greenfield feature design
- Security reviews
```

## 📋 Template Library

### Bug Fixes (Use Haiku)

```
INEFFICIENT (❌):
"I'm having an issue with my authentication. Can you take a look at the
entire auth folder and figure out what's wrong? I think it might be
related to the session handling or maybe the token validation."

EFFICIENT (✅):
"Fix TypeError at auth.ts:156. Expected: function returns Promise<User>.
Current: returns undefined."
```

### Feature Implementation (Start with Opus for planning)

```
PHASE 1 - Planning (Opus):
"Create implementation plan for user profile editing feature.
List: files to modify, new files needed, dependencies, potential risks."

PHASE 2 - Implementation (Haiku):
"Implement the plan from previous message. Create ProfileEdit.tsx
with form validation. Use pattern from SettingsPage.tsx."

PHASE 3 - Testing (Haiku):
"Write tests for ProfileEdit component. Cover: validation, submission, error handling."
```

### Code Search (Efficient Pattern)

```
INEFFICIENT (❌):
"Read all files in src/ and find where we handle user authentication"

EFFICIENT (✅):
"Grep for 'authenticateUser' in src/**/*.ts, then Read the 3 most relevant files."

EVEN BETTER (✅✅):
"Use Explore agent (medium thoroughness) to find authentication implementation"
```

### Debugging (Strategic Model Use)

```
SIMPLE ERROR (Haiku):
"Fix compilation error at line 45 in utils.ts"

COMPLEX BUG (Opus):
"Memory leak in WebSocket connection pool. Connections not closing.
Profile shows 500+ open sockets after 1hr. Need root cause analysis."
```

### Refactoring (Batch Operations)

```
INEFFICIENT (❌):
Read ComponentA.tsx
"Refactor this to use hooks"
Read ComponentB.tsx
"Refactor this to use hooks"
Read ComponentC.tsx
"Refactor this to use hooks"

EFFICIENT (✅):
"Batch refactor ComponentA.tsx, ComponentB.tsx, ComponentC.tsx from
class components to hooks. Use pattern: useState for state, useEffect
for lifecycle. Generate all 3 in one response."
```

### Code Review (Targeted)

```
INEFFICIENT (❌):
"Review my entire codebase and tell me what could be improved"

EFFICIENT (✅):
"Review auth-service.ts for:
1. Security vulnerabilities
2. Error handling gaps
3. Type safety issues
Provide 3-5 highest priority fixes only."
```

## 💡 Prompt Optimization Patterns

### Pattern 1: Specify Exact Lines
```
✅ "Read lines 120-150 from api.ts and extract the rate limiting logic"
❌ "Read api.ts and look for rate limiting"
```

### Pattern 2: Reference Previous Context
```
✅ "Apply the same pattern to UserController.ts"
❌ "Read the pattern from AuthController.ts again and apply it to UserController.ts"
```

### Pattern 3: Use Tool Hints
```
✅ "Grep for TODO comments, then prioritize top 5"
❌ "Find all TODO comments in the project" (triggers expensive file reads)
```

### Pattern 4: Batch Similar Operations
```
✅ "Update imports in: auth.ts, user.ts, profile.ts (all changing from '../lib' to '@/lib')"
❌ Three separate requests for each file
```

### Pattern 5: Clear Success Criteria
```
✅ "Implement login form. Must: validate email format, show loading state, handle network errors.
    Use: Formik for validation, existing Button component."
❌ "Create a login form with good UX"
```

## 📊 Budget-Conscious Workflows

### Daily Coding Session (Budget: $5)

```bash
# Morning: Planning (Opus - $1)
co "Review today's tasks and create implementation plan with time estimates"

# Implementation (Haiku - $2)
ch "Implement tasks 1-3 from plan"
ch "Run tests and fix any failures"
ch "Update documentation"

# Afternoon: Review & Complex Work (Sonnet - $1.50)
cs "Review changes for edge cases and potential bugs"
cs "Optimize the database queries in user-service.ts"

# Cleanup (Haiku - $0.50)
ch "Format code and fix linting issues"
ch "Update changelog"

# TOTAL: ~$5
```

### Emergency Bug Fix (Budget: $2)

```bash
# Step 1: Locate (Haiku - $0.30)
ch "Grep for error: 'Cannot read property userId' in src/"

# Step 2: Analyze (Opus - $1.20)
co "Analyze bug at auth.middleware.ts:67. Stack trace shows null user object.
    Check: session validation, token parsing, database query."

# Step 3: Fix & Test (Haiku - $0.50)
ch "Apply the fix from previous message and run affected tests"

# TOTAL: ~$2
```

## 🚀 Power User Tricks

### Trick 1: Context Priming
```bash
# First request (cache this):
ch "Read: api-design.md, auth-flow.md, database-schema.sql"

# Subsequent requests (reuse cache):
ch "Based on the docs, implement password reset endpoint"
ch "Based on the schema, add user roles table"
# Cache hits save 70-90% on these requests!
```

### Trick 2: Progressive Refinement
```bash
# Instead of one huge request:
ch "Create basic CRUD API for users"           # $0.10
ch "Add validation middleware"                  # $0.05
ch "Add rate limiting"                          # $0.05
ch "Add API documentation"                      # $0.05
# Total: $0.25

# vs. one big request:
co "Create complete production-ready user API" # $0.80
```

### Trick 3: Use Grep Like a Pro
```bash
# Find then act (saves token on reads):
ch "Grep 'class.*Component' in src/, output first 20 matches"
ch "Read the 3 largest components from that list"
ch "Refactor them to functional components"
```

## 🎯 Golden Rules

1. **Default to Haiku** - Use Opus only when stuck
2. **Be specific** - Line numbers > file names > directories
3. **Grep before Read** - Search narrow, then read
4. **Batch operations** - Group similar tasks
5. **Reuse context** - "Use the same pattern" instead of re-reading
6. **Clear context** - `/clear` between unrelated tasks
7. **Check costs** - `/cost` after each session
8. **Set budgets** - Safety nets prevent surprises
