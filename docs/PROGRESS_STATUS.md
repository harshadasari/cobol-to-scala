## Closing report (2026-07-23)

**What this was:** an autonomous, self-perpetuating adversarial-verification campaign against the COBOL-to-Scala conversion engine, run in two phases — an initial 14 rounds (documented in `docs/ADVERSARIAL_ROUNDS_REPORT.md`), paused by owner decision, then resumed at the owner's explicit request and run to a target of round 40. Each round: a Sonnet refuter agent wrote 10-18 adversarial COBOL programs, compiled them with real GnuCOBOL for ground truth, converted them with the engine, and diffed output byte-for-byte; every genuine ("dishonest") finding was fixed and independently re-verified — never trusting a fix agent's own self-report — before being committed.

**Headline numbers:**
- **40 rounds**, **241 total dishonest findings fixed** (110 in rounds 1-14, 131 in rounds 15-40)
- **574 oracle-verified corpus programs** (up from 209 at round 14)
- **~2,017 automated tests**, 0 failures, 45 honest (visibly-marked, individually-documented) todos
- Convergence (0-2 findings/round, sustained) was reached exactly once, at rounds 36-37, before a deliberate strategy broadening in rounds 38-40 found real bugs again at an increasing rate — including two previously entirely-unimplemented statements (`REPLACE`, `PROGRAM-ID ... INITIAL`) discovered as late as round 40

**What got built, not just fixed**, across rounds 15-40: real RECURSIVE-program support (per-activation LINKAGE aliasing, correct BY REFERENCE/CONTENT semantics for scalar/subscripted/GROUP-shaped operands, non-RECURSIVE self-call-cycle detection); a full architectural rewrite of RELATIVE file I/O after discovering the original line-delimited model silently corrupted binary data containing a newline byte (round 29 — the single most serious finding of the whole campaign); real LINAGE and FILE STATUS lifecycle support; real IEEE-754 COMP-1/COMP-2 codecs; and, in the campaign's final round, two genuinely new features (`REPLACE`, `PROGRAM-ID ... INITIAL`) found entirely unimplemented after 39 rounds of searching.

**Process lessons applied throughout** (and worth keeping for any future round): never trust a fix agent's "done"/"tests pass" self-report — independently verify via direct process/file checks every time; a fix agent's own targeted tests can pass while a full-suite regression still slips through (caught once, round 35, before it shipped); a full single-shot test-suite run can get interrupted by the execution environment on long sessions — split into a fast unit-test pass plus a separately-tracked oracle-suite pass with direct PID tracking; an unexpected shift in the honest-todo count is a signal to investigate, not a number to accept at face value (caught a real regression once, and a transient tooling flake once, this way); and even the verification ledger itself needs the same scrutiny as the code — two ledger entries needed after-the-fact reconstruction or correction during this campaign.

**What's genuinely NOT safe to assume works**, for anyone about to point this engine at real production COBOL — see `docs/CAPABILITY_AUDIT_AND_ROADMAP.md` §1.3 for the full, risk-ordered list, but the top three: (1) **reference modification** (`field(start:length)`) still degrades to a placeholder for its actual value almost everywhere — the single largest remaining risk, since it's a common, everyday construct; (2) **`ORGANIZATION IS INDEXED`** (VSAM-style keyed) files are unimplemented, and this project's own sandbox can't even oracle-verify a fix if one were attempted; (3) **`CALL BY REFERENCE`/`CONTENT` of a GROUP containing an OCCURS table into an ordinary (non-recursive) subprogram** silently passes empty/default data instead of the caller's real records.

**Recommended next steps** (not undertaken in this campaign, by design — wrap-up means stopping to hand off, not silently continuing into new feature work): the completeness audit identified reference modification, `SORT ... USING/GIVING`, and extending RECURSIVE-only GROUP+OCCURS aliasing to ordinary calls as the highest-value, most-tractable next targets, given machinery already built elsewhere in the codebase that a future round could plausibly reuse.

## 1. What this run is

You asked whether Fable, running autonomously with subagents, could take this COBOL→Scala conversion engine from "looks complete but silently produces wrong output" to something genuinely verified against real COBOL semantics — across all 4 roadmap phases — over your 2-day window. This is that run.

**The core method (repeated every round):**
1. An adversarial subagent writes 10–14 new, deliberately hostile COBOL programs targeting whatever hasn't been tested yet, compiles each with the *real* GnuCOBOL compiler, and runs `oracleCompare()` — diffing GnuCOBOL's actual output against the generated Scala's actual output.
2. Every mismatch is triaged **HONEST** (a documented, visible gap) or **DISHONEST** (silent wrong output, a crash, or an infinite loop on a claimed-supported feature).
3. A fix subagent closes every dishonest finding, and the winning adversarial programs are **permanently promoted** into the test corpus with the compiler's real output captured as the pass/fail oracle.
4. I (the orchestrator) independently re-run the full suite myself before ever committing — nothing gets marked "done" on a subagent's say-so alone.
5. Repeat until a round finds 0–2 dishonest bugs (convergence) or you call it — **you called it at round 14**.
